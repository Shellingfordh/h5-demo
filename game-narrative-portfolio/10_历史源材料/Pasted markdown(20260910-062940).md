# GOLDEN LIFE 金尘记账 · 产品全景

> 版本：V1.0，2026-09-10 用途：团队对齐产品思路，统一认知 状态：讨论稿，待团队评审

---

## 一、产品是什么

### 1.1 一句话定义

> **用黄金（或用户选择的贵金属）衡量生活的记账 + 任务管理工具。**

### 1.2 完整定义

GOLDEN LIFE 金尘记账不是一个单纯的黄金计算器，也不是一个卖黄金的商城。

它是一款：

> **把现实中的黄金资产、人生经历、目标、消费、故事和时间记录在一起，让每一克黄金都拥有自己的来历，并通过内容、陪伴和分享，让用户愿意持续回来记录自己的"黄金人生"。**

用户第一次打开产品，不应该感觉：

> "这是一个黄金记账 App。"

而应该感觉：

> **"这是一个可以记录我的黄金，也可以记录我的人生的地方。"**

### 1.3 核心价值

| 价值       | 说明                      |
| -------- | ----------------------- |
| **记录生活** | 黄金资产 + 生活收支统一记录         |
| **黄金视角** | 所有金额转换为贵金属等价物（可自选金属/单位） |
| **回顾成长** | 资产价值历史可视化 + 人生时间线       |
| **有温度**  | 每次记录配情绪文案，故事驱动          |
| **有陪伴**  | 猪猪作为情感载体，响应用户行为         |
| **可分享**  | 多维度分享卡，驱动自然增长           |

## 二、产品定位

### 2.1 核心定位

> **一个具有金融数据能力的记账APP，而不是一个能记账的金融App。**

这句话是整个产品的定位锚点：

- **记账是主体**：记录生活、记录黄金、记录人生

* **金融数据是服务**：金价、估值、涨跌等金融信息服务于记账体验，而不是独立强调

- **生活是灵魂**：用黄金衡量生活，而不是用生活追逐金价

### 2.2 我们不是什么

| 不是       | 原因                  |
| -------- | ------------------- |
| 黄金看盘 App | 不跟专业行情产品正面卷 K 线     |
| 黄金投资 App | 不做虚拟黄金、不做交易         |
| 黄金电商 App | 商城不是核心，是自然延伸        |
| 传统记账 App | 不只是记账，而是用黄金衡量生活     |
| 金融 App   | 金融数据服务于记账，不是记账服务于金融 |

### 2.3 我们是什么

> **覆盖黄金的"买之后"场景。**

传统黄金 App 大量集中在：

```
行情 → 价格 → 投资 → 交易 → 购买
```

`────────────────────────────────`

`「买之前」`

我们覆盖：

```
拥有 → 保存 → 记录 → 纪念 → 分享 → 再买
```

`────────────────────────────────`

`「买之后」`

买黄金之后，用户会产生大量非金融行为。传统产品主要覆盖买之前，我们覆盖买之后。

### 2.3 四层产品架构

| 层级         | 内容                    | 说明                   |
| ---------- | --------------------- | -------------------- |
| **第一层：基础** | 金价/克重/估值/计算器/资产记录     | 传统黄金能力，老板不会觉得砍掉了黄金业务 |
| **第二层：生活** | 第一克/父母送的/毕业/婚礼/目标/时间线 | 把黄金变成人生记录的载体         |
| **第三层：内容** | 故事/黄金生活知识/用户故事        | 让产品有温度，不只是工具         |
| **第四层：社交** | 人生卡/年报/目标完成/分享/资产卡    | 驱动增长的传播引擎            |

### 2.5 金融属性定位

> **金融属性不是不要，而是金融数据服务于记账，而不是记账服务于金融。**

| 做            | 不做          |
| ------------ | ----------- |
| 金价作为约合克金的参考  | K线图、技术分析    |
| 持仓估值与盈亏      | 投资建议/收益承诺   |
| 到价提醒（辅助购买决策） | 买涨卖跌引导      |
| 资产记录与历史      | 财富排行榜/资产 PK |
| 黄金商城（实物）     | 充值金豆/虚拟货币   |

**关键原则**：金融功能最终变成服务于记账的功能点，而不是独立的强调点。行情信息弱化到账本的子内容中去——看记录的资产估值走势等，实际上就是变相的行情展示。

### 2.6 信息架构（已决策）

```
账本 · 资产 · ＋ · 发现 · 我的
```

| Tab    | 内容                           | 未来演进                      |
| ------ | ---------------------------- | ------------------------- |
| **账本** | 生活流水 + 贵金属记录 + 估值走势（行情作为子内容） | 核心记账入口，保持不变               |
| **资产** | 资产概览、持仓详情、盈亏                 | → **猪猪的家**（陪伴、互动、情感载体）    |
| **＋**  | 中央凸起按钮，全局录入入口                | 保持不变                      |
| **发现** | 首版：黄金生活知识 + 记账技巧             | → **故事化入口**（故事、用户故事、生活内容） |
| **我的** | 账户、设置、工具、商城入口                | 商城入口仅满足条件时开放              |

**设计逻辑**：

- **账本Tab = 记账主体**：行情信息弱化到账本的子内容中去——看记录的资产估值走势等，实际上就是变相的行情展示。金融数据服务于记账体验，而不是独立强调。

* **资产Tab = 猪猪的家**：猪猪的核心行为是"响应用户的黄金行为"。用户记录黄金→猪猪有反应，查看资产→猪猪陪伴在旁，资产增长→猪猪成长。

- **发现Tab = 故事入口**：首版放轻内容，故事系统就绪后扩展为故事入口。

## 三、目标用户

### 3.1 用户定义

> **18–35 岁年轻黄金消费与持有用户，以女性为核心，但不限定女性。**

不是"攒金女性"——那是行为标签，太窄。

而是"年轻黄金消费与持有用户"，这个范围包含：

| 用户类型        | 典型画像          |
| ----------- | ------------- |
| 买金饰的人       | 25 岁女孩买了一条金项链 |
| 买金豆的人       | 每月买 1g 金豆的年轻人 |
| 买金条的人       | 有资产配置意识的用户    |
| 收到黄金礼物的人    | 妈妈送的金手镯、结婚三金  |
| 婚嫁三金用户      | 准备婚礼的新人       |
| 黄金收藏用户      | 喜欢收集各类金饰      |
| 想开始攒金的人     | 有意愿但还没开始      |
| 已有黄金但没整理的人  | 家里有黄金但不知道多少   |
| 想记录人生黄金资产的人 | 把黄金当人生记录的载体   |

### 3.2 用户分层

| 分层       | 特征          | 产品切入点          |
| -------- | ----------- | -------------- |
| **核心用户** | 已有黄金，想记录和整理 | 资产记录 + 时间线     |
| **种子用户** | 想攒金，需要动力    | 目标系统 + 故事 + 成就 |
| **潜在用户** | 对黄金有兴趣，还没行动 | 计算器 + 故事 + 分享卡 |
| **泛用户**  | 看到分享卡，好奇进来  | 新用户引导 + H5 体验  |

### 3.3 典型用户场景

**场景一：小 A（25岁，刚买第一件金饰）**

- 买了人生第一条金项链，想记录下来

* 打开 App，看到开屏故事"每个人都有属于自己的黄金故事"

- 拍照识别，自动填充克重和价格

* 看到"≈ 0.5g 黄金"的等价物提示

- 生成第一张分享卡，发朋友圈

**场景二：小 B（32岁，有 80g 黄金首饰）**

- 家里有结婚三金、妈妈送的手镯、自己买的金豆

* 想整理清楚到底有多少黄金

- 手动录入每一件，分类管理

* 看到资产历史图表，了解总价值变化

- 设置金价提醒，到价了收到通知

**场景三：小 C（22岁，想开始攒金）**

- 每月买 1g 金豆，想记录进度

* 设置攒金目标，看进度条

- 每次购买后记录，看到成就解锁

* 猪猪做出反应，有陪伴感

- 生成目标卡，分享给朋友

## 四、核心产品理念

### 4.1 黄金不是主角，人生才是主角

产品不是告诉用户：

> "你拥有 36.7g 黄金。"

而是告诉用户：

> "这 36.7g 黄金，陪你经历了什么？"

### 4.2 克重是资产数据，不是财富等级

36.7g 不代表"你比别人有钱"，而代表"这是你目前记录下来的黄金资产"。

**绝对不应该出现**：财富排行榜、资产排名、"击败了多少用户"、黄金等级、充值升级。

### 4.3 记录即成长

猪猪的成长不是虚拟货币驱动的，而是用户真实行为驱动的。

不是"我为了养猪所以每天打开 App"，而是"我在记录自己的黄金人生，而猪猪是这个过程中的一个可视化陪伴"。

### 4.4 设计原则

| 原则              | 说明                             |
| --------------- | ------------------------------ |
| **高频看价、低频录入**   | 账本首屏只回答"这个月花了多少、约合多少克"，录入收进"＋" |
| **真实状态**        | 报价、识别、同步都有时效与失败态，不用"实时"掩盖陈旧    |
| **口径清晰**        | 材料价值、约合克金、回收参考各自标注公式与时间        |
| **动线轻盈**        | 一次记账 4 步内、单屏完成；识别两次点击闭环        |
| **运营痕迹最少**      | 首页不放活动 banner 与弹窗，积分与活动收进"我的"  |
| **用户核对是唯一写入入口** | AI 识别、导入都只生成草稿，用户确认才入账         |

### 5.4 资产与估值

| 能力   | 说明                  | 优先级 |
| ---- | ------------------- | --- |
| 资产概览 | 总估值、今日变化、持仓构成       | P0  |
| 持仓详情 | 各项黄金持仓、克重、成本、盈亏     | P0  |
| 到价提醒 | 到价、保本、价差、幅度四类       | P0  |
| 兑换试算 | 克重与金额双向换算           | P0  |
| 约合克金 | 每笔支出旁显示"≈ 0.05g 黄金" | P0  |
| 行情参考 | 当前金价显示（作为约合克金的参考价）  | P0  |
| 走势简图 | 近期金价走势（简化为一条线）      | P1  |

> **注**：原行情Tab的K线、四金属切换、门店溢价、更多报价等金融分析能力，移入"我的 > 工具"或不做。资产Tab未来演进为**猪猪的家**（陪伴、互动、情感载体）。

### 5.5 通用等价物系统

| 能力     | 说明                |
| ------ | ----------------- |
| 金属选择   | Au/Ag/Pt/Pd 四种贵金属 |
| 单位选择   | g（克）/ 两 / oz（盎司）  |
| 币种选择   | CNY/USD/...       |
| 动态换算   | 每笔收支基于实时金价换算为等价物  |
| 不持久化克重 | 等价物随金价动态重算，不固定    |

### 5.6 事件系统（核心骨架）

| 能力    | 说明                         |
| ----- | -------------------------- |
| 事件发射器 | 所有功能模块发射标准事件               |
| 事件总线  | 统一事件分发 + 事件存储 + 事件查询       |
| 规则引擎  | 事件监听 → 条件匹配 → 触发反馈         |
| 反馈层   | 成就通知 / 猪猪反应 / 分享卡生成 / 故事推进 |

**事件示例**：

| 事件                  | 触发条件     | 反馈                 |
| ------------------- | -------- | ------------------ |
| first\_record       | 首次记账     | 解锁"破冰"成就，猪猪微笑      |
| record\_streak\_7   | 连续记账 7 天 | 解锁"七日不辍"成就，生成连续记录卡 |
| gold\_milestone\_5g | 总克重达 5g  | 解锁"累计 5g"成就，猪猪蹦跳   |
| target\_complete    | 达成攒金目标   | 解锁"目标达成"成就，生成目标卡   |

### 5.7 数据存储与同步

| 原则          | 说明                    |
| ----------- | --------------------- |
| **本地优先**    | 所有写操作先写本地，立即生效        |
| **云端同步**    | 登录态下增量同步，冲突以最后修改为准    |
| **离线可用**    | 无网络时所有功能正常，数据本地队列     |
| **事件以云端为准** | 本地只是预览/预展示，云端下发为决定性内容 |

## 六、发展方向

### 6.1 短期目标（Phase 1，1-2 个月）

> **打好底座，让产品能用。**

- Phase 1a（3 周）：记账底座 + 一般等价物 + 事件系统骨架 + 云同步最小版

* Phase 1b（2-3 周）：Todo 系统 + 成就系统 + 分享卡系统 + Widget + 一句话记账

### 6.2 中期目标（Phase 2，1-2 个月）

> **建立差异化，让用户想用。**

- 故事系统 MVP（《第一克的约定》）

* 猪猪基础（透明存钱罐 + 简单互动）

- 周目系统基础

* AI 账单摘要

- 年度账单报告

### 6.3 长期目标（Phase 3，1-2 个月）

> **完善体验，让用户愿意留。**

- 更多故事 + 周目切换

* 更多成就 + 等级系统

- 商城整合（购买回调 + 自动记录）

* 更多分享卡类型

- 无障碍支持

### 6.4 增长飞轮

```
真实资产 → 人生记录 → 情绪反馈 → 人生瞬间 → 分享
```

`→ 新用户 → 记录 → 商城 → 购买 → 新增资产`

商城不是终点，而是现实资产进入产品的入口之一。

## 八、技术架构要点

### 8.1 技术栈

| 层     | 技术                                  |
| ----- | ----------------------------------- |
| 客户端   | Flutter 3.9 + Riverpod + Hive       |
| UI 组件 | shadcn\_ui + liquid\_glass\_widgets |
| 后端    | Go + Kratos（基于 jinzhi-go-api）       |
| 事件系统  | EventBus → Rule Engine → Feedback   |
| 数据存储  | 本地 Hive（加密）+ 云端同步                   |

### 8.2 代码仓库

| 仓库                  | 用途                          |
| ------------------- | --------------------------- |
| jinzhi-flutter-app  | 源 Flutter 应用（233 个 dart 文件） |
| jinzhi-go-api       | Go 后端（286 个文件）              |
| jinchen-flutter-app | 金尘开发副本（从 jinzhi 复制改造）       |
| jinchen-go-api      | 金尘后端开发副本                    |

### 8.3 架构分层

```
展示层（UI / 动画 / 分享卡 / 主题 / 推送通知）
```

`    ↑`

`反馈层（成就通知 / 猪猪反应 / 分享卡生成 / 故事推进）`

`    ↑`

`规则引擎（事件监听 → 条件匹配 → 触发反馈）`

`    ↑`

`事件总线（统一事件分发 + 事件存储 + 事件查询）`

`    ↑`

`功能层（记账 / Todo / 故事 / 猪猪 / 商城 / 计算器 / 资产）`

### 8.4 数据同步策略

```
用户操作
```

`    ↓`

`本地存储（立即生效，用户无感知延迟）`

`    ↓`

`事件发射（记录变更，触发同步）`

`    ↓`

`同步队列（待同步操作）`

`    ↓`

`网络可用时 → 异步同步到云端`

`    ↓`

`云端存储（后端数据库）`

**关键决策**：

- 事件以云端下发内容为准

* 本地只是预览/预展示

- 冲突以最后修改为准
